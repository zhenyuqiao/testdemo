01 / OVERVIEW

先看全貌

这份材料是以新品研发为核心的流程分权和人员索引手册。它把项目阶段、交付物、系统审批角色和相关人员放在一起，帮助回答“做什么、交什么、谁参与”。

01 · 业务主线

从需求到上市

平台规划、平台开发、单产品企划、产品开发、试产投产，延伸到上市和生命周期管理。

02 · 并行支撑

从专业到交付

技术研究、模块、工业设计、可靠性及物料、图纸、模具、标准，为主线提供能力和受控交付。

03 · 适用分支

按项目选路径

派生、海外差异化、转产、泰国本地化、东芝日本向及编码流程，按实际业务条件适用。

先选项目类型，再查节点。 页面是理解用的归纳，不是可直接照搬的审批名单。线下评审地图中的参会部门，与各分权表中的系统审批角色不是同一回事；具体流程、人员和例外条件请回到原表及当前系统确认。

来源：各子分权更新负责人；1-新品评审地图，第 1–4 行；各项目流程分权表。

01 · PLATFORM PLANNING

平台需求与规划

做什么：从平台需求书进入立项和启动，开展概念工程、工业设计原型、MIS1 论证和平台路演，最后下发平台规划书。

主要输出：MIS1 报告、对标诊断和结论汇总；结构化平台规划书、SKU 配置表。模块与技术需求按需转入对应专业项目。

衔接：原表明确写明，平台规划结项后，系统在相应平台产品开发项目经理账户上自动创建平台开发立项流程。

来源：2-(新)平台规划项目，第 2–30 行。
02 · PLATFORM DEVELOPMENT

平台产品开发

做什么：立项启动后，开展方案设计、可靠性与专利评估、手板摸底测试、结构/性能/电控/电器等专业评审，再进行综合方案评审、模具和方案验证、平台交付。

关键判断：平台综合方案评审是开吸发模具前的综合评审；若所有平台规划书评审结论均为“储备”，原表写明自动触发结项，否则继续后续任务。多个首基准可分别配置开发任务包。

来源：3-(新)平台产品开发项目，第 2–63 行。
03 · PRODUCT PLANNING

单产品企划与决策

做什么：管理市场原始需求、有效需求和简易类需求，完成立项、概念工程、工业设计、可行性与成本评估、专利排查，形成产品策划决策。

主要输出：产品配置及认证需求、技术可行性、新物料清单、目标材料审批表、产品规划书、性能与可靠性目标、项目等级评审、基准配置表及工业设计规格书。

分权重点：审批因项目等级、品牌、市场等变化；新开箱体或箱体发外另有指定审批要求。

来源：4-产品企划类，第 10–92 行。
04 · PRODUCT DEVELOPMENT

产品开发、试制、试产与投产

阶段顺序：立项启动 → 方案设计与专业评审 → DR1 综合方案评审 → 试制及 DR3 试制样机鉴定 → 试产验证及 DR4 投产鉴定 → 项目结项。

贯穿交付：可靠性规划、FBD/DFMEA、测试与问题整改、新物料、EBOM/MBOM、成本、认证、专利及售后资料。不同等级所需交付物和审批深度不同。

特别注意：启动会节点未关闭，不允许发起后续节点关闭流程；试制转试产须完成 100% 封样（85% 正式封样、15% 临时封样）及 MBOM 发放，投产鉴定前须完成 100% 正式封样。PD 类项目结项还需满足首批产合格及稳定量产两个批次等要求。

来源：5-产品开发类项目、方案辅配，第 2–158 行；1-新品评审地图，第 22–33 行；14-变更、新增图纸或零部件、其他类，H23。
05 · MARKET & LIFECYCLE

上市与生命周期管理

做什么：新品评审地图包含上市路演及上市决策；生命周期表进一步管理在销售、退市启动、制造终止、总部停售、退市、冻结以及逆向状态变更。

注意：生命周期表列的是各类变更和对应审批，不意味着所有状态都必须依次经过；部分逆向变更标注“1 年内”，1 年内新品退市还须增加相应审批人员。

来源：1-新品评审地图，第 33–34 行；17-生命周期变更，第 3–63 行。
03 / SUPPORTING FLOWS

分流程：哪些工作支撑主线？

这些流程不是严格排在主流程之后，很多会在不同阶段并行开展。展开查看它们的目标、关键节点与衔接。

技术能力 技术研究：从研究到成果转化

主要环节：技术预研（TRL0–TRL2，含预研评审及结项）；需求论证、技术规划与立项；方案设计与验证（TRL3 至 TRL4/5）；技术验收（TRL6）；成果转化。具体项目按适用流程衔接，不宜把所有环节理解为必经的单一路径。

交付与衔接：验收包括技术、可靠性结论、设计标准初稿、FBD/DFMEA、图纸、成本和封样资料；成果转化关联开发项目编号或首款搭载产品编码。研究验收不等于已量产应用。

来源：8-研究项目流程分权手册，第 3–109 行。

平台能力 模块开发：形成可复用的模块

主线：模块需求评估 → 立项 → 方案设计 → 开模封样 → 模块交付评审 → 结项。需求评估关注必要性、对标、标准化、技术和成本。

阶段条件：方案转阶段要求前置任务合规、A 类问题全部关闭、B 类问题闭环率 85% 以上且 MIS 和摸底测试完成；封样测试阶段需 100% 封样完成；交付需测试通过、系统问题 100% 闭环及新物料封样。

协同：项目组负责辅配、送样、测试跟踪和样品确认，供应链负责寻源和供应商评估；储备项目与转化项目交付资料不同。

来源：9-模块项目流程分权，第 3–30、74–100 行。

设计能力 工业设计：从需求到规格书

主要环节：需求与立项 → 调研 → 效果图提案 → 手板/样品评审 → 结项；CMF 项目另有专用的封样测试节点。

衔接：手板评审关注市场和企划评选、对标结果；结项按 CMF、ID、UI 输出相应规格书或方案，为平台及单产品项目提供工业设计输入。

来源：13-工业设计项目分权，第 2–8 行；2-(新)平台规划项目，第 14–16 行；4-产品企划类，第 42–49 行。

质量能力 可靠性设计：专项项目与主线活动

专项主线：R1 立项 → R2 可行性 → R3 技术方案实施 → R4 结项评审；等级、里程碑、终止、暂停有单独分权，变更需附相关会议纪要。

衔接：可靠性专项不等同于全部可靠性工作，产品及模块项目自身仍有可靠性规划、FMEA、测试和评审要求。

来源：23-可靠性设计类，第 3–43 行；5-产品开发类项目、方案辅配，第 12–18、118–124 行。

项目控制 项目管理变更：计划、责任与状态

适用事项：里程碑、项目经理、等级、终止和暂停等变更；模块项目还单列成本变更。

使用方式：先确认项目属于产品开发、研究、模块还是可靠性，再查各自的变更分权；不同事项的审核范围和所需会议纪要、评审材料不同。

来源：7-开发项目变更分权，第 2–16 行；8-研究项目流程分权手册，第 111–130 行；9-模块项目流程分权，第 121–138 行；23-可靠性设计类，第 32–43 行。

工程数据 样品、图纸、BOM 与工程变更

覆盖范围：送样、零部件委托、样品确认及临时封样、物料试用、电控功能和软件确认；ECR/ECO、通用件变更、MCO；图纸设计/制造发放，以及 EBOM、MBOM、标准化审查和物料编码。

控制点：通用件变更如果也体现在上层 BOM 或图纸中，原表要求同时启动 ECR；ECO 批准是领导决策节点，不能随意把发起人选为批准人。

来源：14-变更、新增图纸或零部件、其他类，第 3–164 行。

制造准备 开模与改模

分支：新品开模、新品有费用改模、无费用改模分别配置审批。模块项目还列出开模申请、招标、模具结构评审、制作、试模和整改的业务链。

衔接：平台综合方案评审位于开吸发模具之前；实际审批应按费用及业务类别查原表。

来源：15-开模流程类，第 3–23 行；9-模块项目流程分权，第 94–96 行；3-(新)平台产品开发项目，第 44 行附近。

制度治理 技术标准：规划、发布与维护

主线：企业标准规划 → 征求意见 → 终稿；另有废弃和临时修订流程。表格列出标准化管理员、主笔、技术分委会及专业人员的节点，并包含分委会、投票人员、票数和例会时间。

边界：该表主要是标准治理和分权，不是各技术标准条文的全文。

来源：16-技术标准系统流程分权，第 1–26 行。

04 / ALTERNATE PATHS

特殊项目怎么走？

海外差异化

不新建整机基准

企划申请 → 必要时工业设计 → 产品开发及测试 → 结项。适用于表中列举的结构差异、新增编码的电源线差异、老品新市场且 BOM 不变的标准升级/认证等情形，具体以原表和引用标准为准。

来源：6-海外不新建基准差异化项目，第 3–13 行。
派生 / 定制

基于已有产品扩展

平台选项集、基准配置、派生需求、定制方案、产品派生和上市决策分开管理。定制需关注母机市场问题整改计划及差异化物料清单，派生需求另有价值链测算。

来源：11-派生流程分权，第 4–15 行。
转产

工厂间生产转移

项目启动 → DR1 综合方案 → 认证资料 → DR4 投产鉴定 → 结项。流程区分转出和转入工厂角色，不能只看单一工厂审批。

来源：10-转产项目分权，第 2–18 行。
泰国本地化

角色映射，而非完整新主线

对产品策划决策、简易需求、开发立项等通用角色映射 TPT 相关岗位，压机辅配另列可靠性人员。

来源：12-泰国本地化分权，第 2–24 行。
东芝日本向

按项目等级使用专表

A/B 与 C/D 级均涵盖商品企划、设计审查、试作认定、量试认定及结项，但人员和日本专家参与要求不同。开发主表也含东芝节点，需结合专表查看。

来源：18、19-东芝南海日本向项目；5-产品开发类项目、方案辅配，第 69、135–155 行。
92 编码

新旧流程适用范围不同

新流程覆盖 BU 需求、机型编制、BOM/参数、业务、认证和专业审核，部分节点按条件跳过。旧流程表注明仅 TPT 和南海东芝产品使用；表中建议及抽查列不应直接合并为现行审批链。

来源：20-新92编码，第 3–21 行；21-旧92编码，第 1–33 行。
05 / CONTROL POINTS

读懂这份手册的五个关键

07 / READ WITH CARE

使用边界与待确认事项

本指南以工作簿可读取的单元格文字为基础。 嵌入图片、隐藏流程图、云盘链接的模板和外部工作簿引用未完整展开核验；本文件也不包含被引用标准的完整正文。请勿把概览当作完整制度或现行系统配置。
  • 项目等级：表中出现 T/I/II/III/IV、A/B/C/D、RA/RB/RT 等体系，但未读到可统一解释全部等级的定义，不能自行推定其对应关系。
  • 海外差异化分类：相关表标题写“5 类”，备注列出四条，需核对源标准或维护人。
  • 领用数量边界：相关表使用小于和大于的条件；数量恰好等于 10 或 100 且另一数量也未触发“大于”条件时，适用流程未明确，执行前应确认。
  • 版本与人员时效：隐藏的“12.26”与可见模块表存在差异，缺乏明确生效关系；各人员表日期也不统一，当前审批角色和人员需核实。
